# Independent standard-user offline Windows test

This is an external evidence requirement, not a developer-host simulation. Use a separately prepared Windows 11 x64 machine or VM with no Visual Studio, Intel compiler/runtime, MS-MPI, Python, WSL or development SDK installation. Use a true standard account, not an administrator account with a filtered token. Record Windows version/build, CPU and RAM, account classification, package SHA256 and how the clean image was prepared. Do not disclose usernames or machine names in a public report.

1. Transfer the exact ZIP and its separately recorded SHA256 to the host. Disconnect networking outside the test program and record that the test is offline. Do not disable security software. Verify the ZIP hash with `Get-FileHash`.
2. Extract under a writable path containing spaces and non-ASCII characters, for example `Documents\Palace test 日本語`. Run the self-contained `Test-CleanHost.ps1` with `-AttestIndependentCleanHost -AttestOffline -OutputRoot '<a separate writable results folder>'`. Use normal PowerShell script execution permitted by the host policy. If policy prevents the script, record `Get-ExecutionPolicy -List`; do not change policy or attempt to evade organizational policy. Manual commands in README.txt remain available for diagnosis.
3. The runner verifies payload hashes, rejects administrator-group membership, records OS/architecture, runs all four examples with one rank/thread and a restricted PATH, checks exit codes and observes app-local vendor modules. It emits a partial machine-readable report. Its success is not the entire gate.
4. Inspect complete C/L matrices and driven/eigen CSVs, compare with the fixed acceptance reference included in `validation/`, and validate all ParaView XML references. Open representative outputs in a separately available ParaView if possible; record its version. The viewer is optional and must not supply runtime dependencies to Palace.
5. Run the driven example, interrupt with Ctrl+C, record exit/termination behavior, then run it again in a fresh output folder. Confirm no MPI service or orphan Palace process was created. Do not delete unrelated user files or processes.
6. Confirm inputs and outputs work outside the extracted application directory. Test a read-only application directory with writable external working/output folders if the host permits setting folder permissions without elevation. Record any unsupported test instead of passing it.
7. Remove the extracted folder. Confirm separately saved model results remain, and no service/system runtime installation or persistent environment change was made. Re-extract and rerun an example.
8. Return report.json, run logs, CSVs, output inventories, package hash, clean/offline preparation record and the manual interruption/re-run/uninstall observations. Gate 0/Gate 5 remain open until this evidence is independently reviewed.

The package remains an internal validation candidate while the redistribution review is open. Do not publish it or infer redistribution rights from successful execution.

## Automated kit entry point

`Test-CleanHost.ps1 -OutputRoot <new-user-writable-folder> -AttestIndependentCleanHost -AttestOffline` invokes the three-path suite. It rejects administrator-group membership and a bounded inventory of excluded products/services, verifies every payload hash, runs all four examples twice per path, observes every app-local DLL, checks missing-input and unsupported-ParMETIS failures followed by recovery, validates finite CSV/VTU arrays and XML references using only Windows PowerShell/.NET, and exports Touchstone. It copies the package to new ASCII, whitespace and Japanese paths; it never alters the frozen package. Keep enough space for three copies and 24 solver output sets.

The package also contains Test-Paths.ps1 with an explicit DeveloperHost switch for engineering diagnostics. Those reports are always labeled DEVELOPER_HOST_ONLY and cannot pass Gate 5. An independent clean environment is not currently available; its absence is an execution blocker, not a package defect or a legal decision. Manual image preparation, network-attempt observations, Ctrl+C, uninstall/cleanup and returned-data numerical review remain required even if the automated suite passes.
